\#\# Commit Message Format\* Use the format: `type(scope): summary`
\* Types: feat, fix, docs, style, refactor, test, chore\* Scope is optional and should be a short area name.
\* Summary: present tense, imperative, max72 chars.

\#\# Rules\* One line only.
\* No trailing period.
\* Prefer clarity over cleverness.
\* Mention breaking changes with `!` after type, e.g., `feat!(api): change response shape`.
\* No more than 50 characters in the summary.
\* Use the body to explain what and why, not how.
\* Separate body from summary with a blank line.
\* Use bullet points in the body if needed.

\#\# Examples\* `feat(auth): add JWT support`
\* `fix(ui): resolve button alignment issue`
\* `docs: update README with setup instructions`
\* `refactor: simplify user service logic`
\* `test: add unit tests for payment processing`
\* `chore: update dependencies to latest versions` 

\#\# Benefits\* Improves readability and consistency of commit history.
\* Makes it easier to understand the purpose of each commit at a glance.
\* Facilitates automated changelog generation and release notes.
